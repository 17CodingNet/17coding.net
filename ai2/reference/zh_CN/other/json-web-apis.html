使用带 JSON 的 Web API

JavaScript 对象表示法（JavaScript Object Notation，JSON）广泛用于与 Web 上的应用程序编程接口（API）交互。JSON 提供了若干用于组合消息的类型。App Inventor 同样支持这些值。

  • JSON 值 true 和 false 会变成 App Inventor 的 true 和 false
  • JSON 数字（包括整数和小数）会变成 App Inventor 的 number
  • JSON 字符串会变成 App Inventor 的 text
  • JSON 数组会变成 App Inventor 的 list
  • JSON 对象会变成 App Inventor 的 dictionary

一条 JSON 消息的示例如下：

{
  "name": "Tim Beaver",
  "likes": ["dams", "engineering"],
  "hasTowel": true,
  "widgets": 42
}

这段 JSON 声明了一个对象（由 { 和 } 表示）。键是冒号（:）前面那些带引号的字符串（例如 "name"）。可以看到其中包含不同类型的值，包括数组（方括号 [...] 之间以逗号分隔的值）、数字（例如 42）和布尔值（例如 true）。

在本文余下的部分中，我们将使用一个名为 JSONPlaceholder 的服务，它专门用于示例演示。它会以 Lorem Ipsum 的形式生成示例 JSON 响应，并不会真正存储任何数据。

获取数据

Web 组件提供了 Get 方法。请求完成后，Web 的 GotText 事件块就会运行。该事件有两个重要的参数：

  • responseCode：服务器返回的 HTTP 状态码。通常会是 200（OK）或 201（Created），但也可能得到 400（Bad Request）、403（Forbidden）、404（Not Found）之类的值。根据应用中使用的 API，您应当检查状态码，以判断请求是否成功。
  • responseContent：服务器返回的响应内容，类型为 text。下面看看如何把它按 JSON 处理：

Web 组件提供了 JsonTextDecodeWithDictionaries 方法，它接受一个 text（例如 responseContent 参数的内容），并把它转换成相应的 App Inventor 类型。根据返回内容的不同，JsonTextDecodeWithDictionaries 的输出可能是不同的类型，例如 list 或 dictionary。如果 API 可能返回不止一种类型的内容，您可以用 App Inventor 提供的 is a list? 和 is a dictionary? 等块来检测该值。
