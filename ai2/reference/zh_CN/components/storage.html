云数据库（CloudDB）

CloudDB 组件是一个非可视组件，它允许您把数据存储在接入互联网 的数据库服务器上（使用 Redis 软件）。这使您的应用的用户可以彼此共享 数据。默认情况下，数据会存储在由 MIT 维护的服务器上，不过您 也可以自行搭建并运行自己的服务器。设置 RedisServer 属性和 RedisPort 属性即可访问您自己的服务器。

属性

ProjectID
获取此 CloudDB 项目的 ProjectID。
RedisPort
要使用的 Redis 服务器端口。默认为 6381
RedisServer
用于存储数据的 Redis 服务器。设为“DEFAULT”表示将使用 MIT 的服务器。
Token
此字段包含用于登录后端 Redis 服务器的身份验证令牌。对于 “DEFAULT”服务器，请勿编辑此值，系统会为您填入。系统 管理员也可能向您提供一个特殊值，用于在多个人的多个 项目之间共享数据。如果使用您自己的 Redis 服务器，请在 服务器的配置中设置密码并在此处输入。
UseSSL
设为 true 以使用 SSL 与 CloudDB/Redis 服务器通信。对于“DEFAULT”服务器，应将其设为 True。

事件

CloudDBError(message)
表示与 CloudDB Redis 服务器通信时发生错误。
DataChanged(tag,value)
表示 CloudDB 项目中的数据已更改。引发一个事件，其中带有已更新的 tag 及其现在具有的 value。
FirstRemoved(value)
由 RemoveFirstFromList 函数触发的事件。参数 value 是列表中第一个、现在已被 移除的对象。
GotValue(tag,value)
表示 GetValue 请求已成功。
TagList(value)
收到已知标签列表时触发的事件。作为对 GetTagList 函数调用的响应而运行。
UpdateDone(tag,operation)
表示向 CloudDB 存储数据的操作已完成。

方法

AppendValueToList(tag,itemToAdd)
以原子方式把一个值追加到列表末尾。如果两台设备同时使用此函数，两个值都会被追加，不会丢失数据。
ClearTag(tag)
从 CloudDB 中移除该标签。
CloudConnected()
如果我们处于联网状态且很可能能够连接到 CloudDB 服务器，则返回 true。
GetTagList()
要求 CloudDB 检索属于此项目的所有标签。 结果列表在 TagList 事件中返回。
GetValue(tag,valueIfTagNotThere)
GetValue 要求 CloudDB 获取存储在给定标签下的值。 它会把结果传递给 GotValue 事件。
RemoveFirstFromList(tag)
获取列表的第一个元素并以原子方式移除它。如果两台设备同时使用此函数， 一台设备将得到第一个元素，另一台将得到第二个元素， 如果没有可用元素则会出错。当元素可用时，将触发 FirstRemoved 事件。
StoreValue(tag,valueToStore)
要求 CloudDB 把给定的 value 存储在给定的 tag 下。

数据文件（DataFile）

允许读取 CSV 和 JSON 数据的组件。DataFile 包含以行或列的形式访问 CSV 或 JSON 解析数据的功能。可以与 ChartData2D 组件配合使用，把数据 直接从文件导入 Chart。在成功选择并解析文件之后， 也可以把该组件拖放到 Chart 上，以便从文件自动在 Chart 上创建 ChartData 组件。

属性

ColumnNames
获取当前加载的源文件的列名。 对于 CSV 文件，这将返回第一行中各项的列表。 对于 JSON 文件，这将返回 JSON 对象中各个键的列表。
Columns
获取当前加载的源文件的列组成的列表。
DefaultScope
指定使用 File 组件访问文件时的默认范围。对大多数应用来说，App（应用目录）范围 即可正常工作。对于在 Android 对应用文件访问施加较新约束之前 就存在的应用，可以使用 Legacy（旧版目录）模式。
Rows
获取当前加载的源文件的行组成的列表。
SourceFile
设置要从中解析数据的源文件，然后 异步解析该文件。结果存储在 Columns、 Rows 和 ColumnNames 属性中。 该文件的预期格式为 CSV 或 JSON 格式。

事件

无

方法

ReadFile(fileName)
表示要从中加载数据的源文件。该文件内容的预期格式 为 CSV 或 JSON。在 fileName 前加 / 可读取 SD 卡上的特定文件（例如，/myFile.txt 将读取文件 /sdcard/myFile.txt）。要读取随应用打包的素材（对 伴侣也适用），请让 fileName 以 //（两个斜杠）开头。如果 fileName 不以斜杠开头，则将（对打包的应用）从应用的 私有存储中读取，对伴侣则从 /sdcard/AppInventor/data 中读取。

文件管理器（File）

用于存储和获取文件的非可视组件。使用此组件在设备上写入或读取 文件。

外部文件的确切存放位置取决于 Scope 属性的值、应用是在伴侣中运行还是已编译， 以及应用运行在哪个 Android 版本上。

由于较新版本的 Android 要求把文件存储在应用专属目录中， DefaultScope 被设为 App。如果您使用的是较旧版本的 Android 并且需要访问 旧版的公共存储，请把 DefaultScope 属性改为 Legacy。您也可以使用 块来更改 Scope。

下面我们简要说明每种范围类型：

  • App（应用目录）：在 Android 2.2 及更高版本上，文件将从应用专属存储中读取并写入 其中。在更早的 Android 版本上，文件将写入旧版存储。
  • Asset（素材目录）：文件将从应用素材中读取。尝试写入应用 素材会出错，因为它们位于只读存储中。
  • Cache（缓存目录）：文件将从应用的缓存目录中读取并写入其中。Cache 对于 可以重新创建的临时文件很有用，因为它允许用户清除临时文件以收回 存储空间。
  • Legacy（旧版目录）：文件将按 App Inventor 在 nb187 版本之前的规则 从文件系统中读取并写入其中。也就是说，以单个 / 开头的文件名将从 外部存储目录的根目录（例如 /sdcard/）中读取并写入其中。旧版功能 在 Android 11 或更高版本上不会工作。
  • Private（私有目录）：文件将从应用的私有目录中读取并写入其中。使用此范围 存储不应对其他应用（例如文件管理类应用）可见的 信息。
  • Shared（共享目录）：文件将从设备的共享媒体目录（例如 Pictures）中读取并写入其中。

注 1：在 Legacy（旧版目录）模式下，文件名可以有以下三种形式之一：

  • 私有文件没有前导 /，写入应用私有存储（例如 "file.txt"）
  • 外部文件有一个前导 /，写入公共存储（例如 "/file.txt"）
  • 打包的应用素材有两个前导 //，并且只能读取（例如 "//file.txt"）

注 2：在所有范围中，以两个斜杠（//）开头的文件名都将被解释为 素材名。

属性

DefaultScope
指定使用 File 组件访问文件时的默认范围。对大多数应用来说，App（应用目录）范围 即可正常工作。对于在 Android 对应用文件访问施加较新约束之前 就存在的应用，可以使用 Legacy（旧版目录）模式。
ReadPermission
一个仅设计视图的属性，可用于启用对 应用专属目录之外的文件存储的读取访问。
Scope
表示 ReadFrom 和 SaveFile 等操作的当前范围。
WritePermission
一个仅设计视图的属性，可用于启用对 应用专属目录之外的文件存储的写入访问。

事件

AfterFileSaved(fileName)
表示文件内容已写入的事件。
GotText(text)
表示已从文件读取内容的事件。

方法

AppendToFile(text,fileName)
把文本追加到文件末尾。如果文件尚不存在则创建它。有关 文件写入位置的信息，请参阅 SaveFile 下的帮助文本。 成功后，将运行 AfterFileSaved 事件。
CopyFile(fromScope,fromFileName,toScope,toFileName)
把第一个文件的内容复制到第二个文件。
Delete(fileName)
从存储中删除文件。在 fileName 前加 / 可删除 SD 卡中的特定 文件（例如，/myFile.txt 将删除文件 /sdcard/myFile.txt）。 如果 fileName 不以 / 开头，则将删除位于 程序私有存储中的文件。让 fileName 以 // 开头 会出错，因为素材文件不能删除。
Exists(scope,path)
测试给定范围中该路径是否存在。
IsDirectory(scope,path)
测试给定范围中命名的路径是否为目录。
ListDirectory(scope,directoryName)
获取给定目录中的文件和目录列表。
MakeDirectory(scope,directoryName)
创建一个用于存储文件的新目录。此方法的语义是：它在 完成时如果目录存在则返回 true。这可能意味着该目录在调用之前 就已经存在。
MakeFullPath(scope,path)
把范围和路径转换成一个字符串，供其他组件使用。
MoveFile(fromScope,fromFileName,toScope,toFileName)
把文件从一个位置移动到另一个位置。
ReadFrom(fileName)
从存储中的文件读取文本。在 fileName 前加 / 可从 SD 卡上的特定文件读取（例如，/myFile.txt 将读取文件 /sdcard/myFile.txt）。要读取随应用打包的素材（对 伴侣也适用），请让 fileName 以 //（两个斜杠）开头。如果 fileName 不以斜杠开头，则将（对打包的应用）从应用的 私有存储中读取，对伴侣则从 /sdcard/AppInventor/data 中读取。
RemoveDirectory(scope,directoryName,recursive)
从文件系统中移除目录。如果 recursive 为 true，则移除其中的所有内容。如果 recursive 为 false，则只移除该目录，且仅当它为空时。
SaveFile(text,fileName)
把文本保存到文件。如果 fileName 以斜杠（/）开头，则文件 写入 sdcard（例如，写入 /myFile.txt 会把文件写到 /sdcard/myFile.txt）。如果 fileName 不以斜杠开头，则将 写入程序的私有数据目录，其他程序无法访问。对于 AI 伴侣 有一个特殊例外：这些文件会写入 /sdcard/AppInventor/data 以便于调试。

注意，如果文件已存在，此块会覆盖它。如果想向现有文件添加内容， 请使用 AppendToFile 方法。

电子表格（Spreadsheet）

电子表格是一个非可视组件，用于使用 Google Sheets API 向 Google Sheets 文档存储数据以及从中接收数据。

要使用此组件，首先必须拥有一个 Google 开发者 账号。然后，必须在该 Google 开发者 账号下创建一个新项目，在该项目上启用 Google Sheets API，最后为 Sheets API 创建一个服务账号。

有关如何创建服务账号的说明，以及在哪里可以找到 使用 Google 表格组件的其他相关信息， 请见此处。

行号和列号从 1 开始计数。

属性

ApplicationName
应用的名称，在发起 API 调用时使用。
CredentialsJson
包含服务账号凭据的 JSON 文件
SpreadsheetID
您要编辑的 Google Sheets 文件的 ID。您可以在 Google Sheets 文件的 URL 中找到 spreadsheetID。请查找 URL 中 '/d/' 与 '/edit' 之间的部分，例如在 https://docs.google.com/spreadsheets/d/1234abcd/edit 中，ID 为 '1234abcd'。

事件

ErrorOccurred(errorMessage)
每当 API 调用遇到错误时触发。有关错误的详细信息在 errorMessage 中。
FinishedAddColumn(columnNumber)
AddColumn 块的回调事件，在表中的 值更新后调用。此外，它还返回 新列的列号。
FinishedAddRow(rowNumber)
AddRow 块的回调事件，在表中的 值更新后调用。此外，它还返回 新行的行号。
FinishedAddSheet(sheetName)
addSheet 块的回调事件，在表中的值更新后调用。
FinishedClearRange()
ClearRange 块的回调事件，在表中的 值更新后调用。
FinishedDeleteSheet(sheetName)
DeleteSheet 块的回调事件，在表中的值更新后调用。
FinishedRemoveColumn()
RemoveColumn 块的回调事件，在表中的 值更新后调用。
FinishedRemoveRow()
RemoveRow 块的回调事件，在表中的 值更新后调用。
FinishedWriteCell()
WriteCell 块的回调事件，在表中的 值更新后调用。
FinishedWriteColumn()
WriteColumn 块的回调事件，在表中的 值更新后调用。
FinishedWriteRange()
WriteRange 块的回调事件，在表中的 值更新后调用。
FinishedWriteRow()
WriteRow 块的回调事件，在表中的 值更新后调用。
GotCellData(cellData)
ReadCell 块的回调事件。cellData 是 单元格中的文本值。
GotColumnData(columnData)
ReadColumn 块的回调事件。columnData 是 按行号递增顺序排列的单元格文本值列表。
GotRangeData(rangeData)
ReadRange 块的回调事件。rangeData 是 行组成的列表，其维度与 rangeReference 相同。
GotRowData(rowDataList)
ReadRow 块的回调事件。rowDataList 是 按列号递增顺序排列的单元格文本值列表。
GotSheetData(sheetData)
ReadSheet 块的回调事件。sheetData 是 行组成的列表。
GotSheetList(sheetNames)
ListSheets 块的回调事件，在检索到工作表列表后调用。

方法

AddColumn(sheetName,data)
给定一个值列表作为 data，把值追加到工作表的下一个空 列。它总是从顶行开始并向下继续。完成后， 触发 FinishedAddColumn 回调事件。
AddRow(sheetName,data)
给定一个值列表作为 data，把值追加到工作表的下一个 空行。它总是从最左侧的列开始并向右继续。完成后， 触发 FinishedAddRow 回调事件。此外，它还返回新行的行号。
AddSheet(sheetName)
在电子表格中添加一个新工作表。
ClearRange(sheetName,rangeReference)
清空给定范围内的单元格。完成后，此块触发 FinishedClearRange 回调事件。
DeleteSheet(sheetName)
删除电子表格中指定的工作表。
GetCellReference(row,column)
把行和列的整数表示转换为 Google Sheets 中用于单个单元格的 A1 记号法。例如，第 1 行第 2 列 对应字符串 "B1"。
GetRangeReference(row1,column1,row2,column2)
把范围各角的行和列的整数表示 转换为 Google Sheets 中使用的 A1 记号法。例如，选择从 第 1 行第 2 列到第 3 行第 4 列的范围对应字符串 “B1:D3”。
ListSheets()
列出电子表格中所有工作表的名称。触发 GotSheetList 回调事件，并带有工作表名称列表。
ReadCell(sheetName,cellReference)
在具有所提供 sheetName 的页面上，读取给定 cellReference 处的单元格并触发 GotCellData 回调事件。 cellReference 可以是带有 A1 记号法的文本块，也可以是 GetCellReference 块的结果。
ReadColumn(sheetName,column)
在具有所提供 sheetName 的页面上，读取给定 colNumber 处的列并触发 GotColumnData 回调事件。
ReadRange(sheetName,rangeReference)
在具有所提供 sheetName 的页面上，读取给定 rangeReference 处的单元格并触发 GotRangeData 回调事件。 rangeReference 可以是带有 A1 记号法的文本块，也可以是 GetRangeReference 块的结果。
ReadRow(sheetName,rowNumber)
在具有所提供 sheetName 的页面上，读取给定 rowNumber 处的行并触发 GotRowData 回调事件。
ReadSheet(sheetName)
读取整个 Google Sheets 文档并触发 GotSheetData 回调事件。
ReadWithExactFilter(sheetName,colID,value)
筛选 Google Sheet，找出给定列号与所提供的值匹配的行。
ReadWithPartialFilter(sheetName,colID,value)
筛选 Google Sheet，找出给定列号包含所提供值字符串的行。
RemoveColumn(sheetName,column)
从表中删除具有给定列号的列。这 不会清空该列，而是将其整个移除。工作表的网格 id 可以 在 Google Sheets 文档 URL 的末尾、“gid=”之后 找到。完成后，触发 FinishedRemoveColumn 回调事件。
RemoveRow(sheetName,rowNumber)
从表中删除具有给定行号（从 1 开始计数）的行。这 不会清空该行，而是将其整个移除。工作表的网格 id 可以 在 Google Sheets 文档 URL 的末尾、“gid=”之后 找到。完成后，触发 FinishedRemoveRow 回调事件。
WriteCell(sheetName,cellReference,data)
给定文本或数字作为 data，把值写入该单元格。它会 用所提供的值覆盖单元格中任何现有的数据。完成后， 触发 FinishedWriteCell 回调事件。
WriteColumn(sheetName,column,data)
给定一个值列表作为 data，把值写入具有 给定列号的列，自上而下覆盖现有值。（注意：它 不会擦除整列。）完成后，触发 FinishedWriteColumn 回调事件。
WriteRange(sheetName,rangeReference,data)
给定列表的列表作为 data，把值写入范围内的单元格。范围中 的行数和列数必须与您的数据的维度匹配。此方法会覆盖 范围内现有的数据。完成后， 触发 FinishedWriteRange 回调事件。
WriteRow(sheetName,rowNumber,data)
给定一个值列表作为 data，把值写入具有 给定行号的行，自左向右覆盖现有值。（注意：它 不会擦除整行。）完成后，触发 FinishedWriteRow 回调事件。

本地数据库（TinyDB）

TinyDB 是一个为应用存储数据的非可视组件。

使用 App Inventor 创建的应用每次运行时都会重新初始化。这意味着，如果应用 设置了某个变量的值，之后用户退出了应用，那么该变量值在 下次运行应用时不会被记住。相比之下，TinyDB 是应用的持久数据存储。 存储在 TinyDB 中的数据在每次运行应用时都可用。一个例子 是游戏保存最高分，并在每次玩游戏时取出它。

数据项由标签和值组成。要存储一个数据项，您需要指定它应存储 在哪个标签下。标签必须是文本块，用于给数据命名。随后，您可以 取出存储在给定标签下的数据。

您不能用 TinyDB 在手机上的两个不同应用之间传递数据，不过您 可以用 TinyDB 在多屏幕应用的不同屏幕之间共享数据。

当您使用 AI 伴侣（Companion）开发应用时，所有使用该伴侣的应用都会 共享同一个 TinyDB。一旦应用打包并安装到手机上，这种共享就会 消失。在开发过程中，每次开始处理新应用时，您都应小心清除 伴侣应用的数据。

属性

Namespace
用于存储数据的命名空间。

事件

无

方法

ClearAll()
清空整个数据存储。
ClearTag(tag)
清除具有给定 tag 的条目。
GetEntries()
以字典形式获取所有数据的方法
GetTags()
返回数据存储中所有标签的列表。
GetValue(tag,valueIfTagNotThere)
取出存储在给定 tag 下的值。如果没有这样的标签，则 返回 valueIfTagNotThere。

网络数据库（TinyWebDB）

TinyWebDB 组件与一个 Web 服务通信，以存储 和获取信息。尽管此组件可以使用，但它 非常有限，主要是作为演示，供想要创建自己的、与 Web 通信的 组件的人参考。 随附的 Web 服务位于 (http://tinywebdb.appinventor.mit.edu)。该组件具有 在标签下存储值以及 取出与该标签关联的值的方法。 “存储”和“取出”的含义 由 Web 服务决定。在此实现中，所有标签和 值都是字符串（文本）。此限制在 未来的版本中可能会放宽。

属性

ServiceURL
指定 Web 服务的 URL。 默认值是运行在 App Engine 上的演示服务。

事件

GotValue(tagFromWebDB,valueFromWebDB)
表示 GetValue 服务器请求已成功。
ValueStored()
表示 StoreValue 服务器请求已成功的事件。
WebServiceError(message)
表示与 Web 服务的通信发出了错误信号。

方法

GetValue(tag)
GetValue 要求 Web 服务获取存储在给定 tag 下的值。 如果该 tag 下没有存储值，返回什么由 Web 服务决定。 此组件只接受返回的任何内容。 GotValue 事件将在完成时运行。
StoreValue(tag,valueToStore)
向 Web 服务发送请求，把给定的 valueToStore 存储在 给定的 tag 下。ValueStored 事件将在完成时运行。
